# cabicad-frontend
Frontend for CabiCAD

## Stack
- React 19 + TypeScript + Vite
- three.js via React Three Fiber (`@react-three/fiber`) + helpers from `@react-three/drei` for the 3D room / furniture view

## Run
```bash
npm install
npm run dev     # http://localhost:5173 (proxies /api -> http://localhost:8080)
npm run build   # typecheck + production build
```

## Backend integration
- Start `cabicad-backend` (`./gradlew bootRun`, port 8080), then `npm run dev`.
- Vite dev (`:5173`) and preview (`:4173`) servers proxy `/api/**` to `VITE_BACKEND_URL` (default `http://localhost:8080`), so the app calls the API with relative URLs – no CORS setup needed.
- All requests go through `src/api/client.ts` (`apiGet`); set `VITE_API_BASE_URL` to call the backend directly instead of via the proxy. See `.env.example`.
- Board catalog: `GET /api/boards/catalog` (board models for the "Płyta" picker) and `GET /api/boards/{id}/texture` (texture image proxy) – see "Board models" below.

## 3D scene (single furniture workspace)
Units: **millimetres** – the base unit of the whole app (board dimensions, positions and the scene: 1 scene unit = 1 mm). Y axis up, floor on the XZ plane. Workspace 4000 × 4000 mm (dashed outline), grid 100 mm / 1000 mm, axes X red / Y green / Z blue (1000 mm) and a red dot at the furniture origin (see below). Scene constants in `src/scene/sceneConfig.ts`.

Mouse controls (`src/scene/CameraRig.tsx`):
- wheel – zoom in / out (towards the cursor)
- left button + drag – pan (move the camera)
- right button + drag – rotate the camera
- **W / A / S / D** – move the camera forward / left / back / right together with its target, in the horizontal plane, **Q / E** – down / up (`src/scene/cameraKeys.ts`); speed follows the zoom (60 % of the camera–target distance per second), **Shift** ×3. Ignored while typing in a field / drop-down and in the 2D editor windows; physical key codes, so it works on any keyboard layout. **Sterowanie** (`src/scene/ControlsHint.tsx`, top right under *Światło*, collapsible like it) lists the mouse and all keyboard shortcuts plus the help of the current tool / selected board.
- **Światło** (top right of the viewport, `src/scene/LightControl.tsx`, model `src/scene/lighting.ts`): a disk seen from above with the furniture in the middle (front = bottom edge, red) – drag the sun around it to choose the side the key light comes from, towards the centre for a higher light (centre = from above, rim = 5°, low from the side); arrow keys on the disk (←/→ direction, ↑/↓ height, Shift = bigger steps), presets *Z góry / Z przodu / Z boku*, sliders for the light and the ambient intensity, *Przywróć domyślne* (the former fixed light: front-right, 49°). The settings are remembered in the browser (localStorage). The shadow camera follows the light (`KeyLight` in `Scene.tsx`). In the scene a glowing **sun** (`src/scene/SunMarker.tsx`) floats far above the furniture in the light direction and moves with it (zoom out / orbit to see it); the *Pokaż promienie* button in the *Światło* panel (off by default, remembered in the browser) adds a dashed ray from the sun to the furniture. The sun casts no shadow and can't be clicked.
- "Resetuj widok" button – back to the default view showing the whole workspace

## Furniture (mebel)
- Left tool panel → **Parametry mebla** (`src/panels/FurniturePanel.tsx`): height / width / depth of the furniture [mm] (model in `src/furniture/furniture.ts`, default 800 × 720 × 560, limits 50–4000 / 50–3000 / 50–4000).
- The furniture is a cuboid and at the same time the **working volume of the boards** – drawn in the scene as a blue outline of its edges (`src/scene/FurnitureBox.tsx`). It is centred on the workspace floor (offset snapped to the 100 mm floor grid).
- **Furniture coordinate system** – all board positions are measured from its origin = the left-top corner of the furniture's bottom plane (seen from above, front at the bottom) = left-back-bottom corner of the cuboid, marked with the **red dot**: X → right (0…width), Y → up (0…height), Z → front (0…depth).
- The furniture cannot be made smaller than the space already occupied by the boards (the minimum of each field grows with the boards). Boards bound to the far furniture wall by layout constraints don't limit it – they move / stretch with the furniture.

## Boards (płyty)
- Left tool panel (`src/panels/ToolPanel.tsx`), grouped: **Mebel** → *Parametry mebla*; **Płyty** → *Dodaj płytę*, *Płyty* (with the number of boards); **Sekcje mebla** → *Półki i Przedziały*, *Fronty* (later *Szuflady*) – in these tools a section is picked in the scene / list and single boards cannot be selected (`SECTION_TOOLS`; the same in *Parametry mebla*). Every button opens its helper panel, which floats OVER the left edge of the scene (the scene keeps its size – it does not jump when a panel opens, closes or has a different width) and slides in / out (0,22 s, off with *prefers-reduced-motion*).
- **Dodaj płytę** (`src/panels/AddBoardPanel.tsx`): on top **Płyty korpusu** (`CarcassPanel`, see below), below **Pojedyncza płyta** – the form of a free board. Hovering previews what would be added as a green wireframe: the top tile of *Płyty korpusu* (with *Dodaj cały korpus / Dodaj brakujące płyty*) – all carcass boards not added yet, the tile of a role not added yet – that board (placed exactly where its joints will put it); the single board form – the new board in the centre of the furniture, with its dimensions. After *Dodaj płytę* the new board opens selected in **Płyty**.
- **Płyty** (`src/panels/BoardsPanel.tsx`): all added boards (carcass, shelves / partitions, fronts, single boards) – a card per board, the expanded card edits it. A board clicked in the scene opens here; *Szczegóły* in the other panels too.
- **Parametry mebla** edits the furniture as a whole – boards cannot be selected in the scene then.
- Parameters: thickness / height / width (mm) and orientation: **pionowa (wzdłuż szerokości)** (vertical, XY plane – front / back), **pionowa (wzdłuż głębokości)** (side, YZ plane – width = depth along Z, thickness along X; 2D view from the right, edge D at the front) or **pozioma** (horizontal, XZ plane – lies on the floor).
- **Dodaj** renders the board in the scene (`src/boards/BoardMesh.tsx`, geometry mapping in `src/boards/board.ts`).
- Every board has a **position** [mm] = its corner with the smallest X / Y / Z in the furniture coordinate system (Y = 0 → on the bottom of the furniture). A new board is created in the **centre of the furniture** (`centeredPosition`: its centre = the furniture centre on every axis, rounded to 0,1 mm; a board as big as the furniture sits at 0). It may overlap existing boards – shown as a collision – and is then moved / joined. After **Dodaj** the new board is selected (green edges, dimensions).
- **Preview before adding**: while the mouse is over the "Nowa płyta" section of the panel (and no board is selected) the board it would add is drawn in the scene as a **green wireframe** with a faint green fill, exactly where it will appear, with its dimensions (`draftBoard`, `src/boards/DraftBoard.tsx`). It follows every change in the form (dimensions, orientation, cut-outs); it is not clickable and disappears when the mouse leaves that section, the panel closes or a board is selected.
- **Dimensions of the selected board** (`src/boards/DimensionLabels.tsx`) – styled like the X / Y / Z axes at the origin: a dimension line 45 mm beyond edge A (width) and beyond edge D (height), in the plane of the board, with thin extension lines from the corners, in the colour of the world axis it runs along (X red, Y green, Z blue), and the value in mm on the line (light pill background, shifted from the middle towards B / C so it does not cover the A / D letter) (gross dimensions, incl. edge bands). Drawn on top of everything, for the selected board and the preview.
- Below the add section the helper panel lists the added boards (`src/panels/BoardCard.tsx`): **Edytuj** opens inline editing of dimensions, orientation and position (valid changes are applied to the scene immediately), **Usuń** removes the board. Overlapping boards are marked "Koliduje z: …" in the list and drawn in red in the scene.

## No edge bands where boards touch (`src/layout/edgeContacts.ts`)
- An **edge** (narrow face) of a board that **touches another board** gets no edge band – a band inside a joint makes no sense. A contact = OPPOSITE faces of two boards in one plane with a shared area, **with or without a joint** (so also for boards without joints or placed by hand); the face of each board that is an edge (not its large surface) and has a band loses it. Touching a furniture wall does not count. E.g. default carcass: the sides lose the top band (under the top), the bottom its left / right bands, the back all four; a shelf its left / right / back bands.
- Derived, not stored (`hiddenBands`): the configuration keeps its bands, but wherever the banding is USED it is left out on those edges – render, edge labels, board tile (crossed-out letter + "bez obrzeża (przylega): D → Lewy bok"), 2D view, shape / band validation. So no way of setting a finish can put a band on a touching edge: the board form, "Dodaj płytę" defaults, the carcass / section / furniture defaults and all their **Zastosuj** buttons.
- **Locked in the band form**: a touching edge shows "Brak (przylega)" (disabled) with the board it touches, and a hint lists those edges; the cut-out editor works on the shown banding and never writes the hidden edges back (`restoreHiddenBands`). Move the board away / remove the neighbour and the configured band is back.

## Default finish of the furniture
- **Parametry mebla** → **Płyta i obrzeże mebla** (board model + thickness + grain + obrzeże ABS incl. per-edge overrides): the default of ALL more specific configurations, which inherit it unless they have their own:
  - new ordinary boards ("Nowa płyta" form – it takes over the furniture finish when that changes),
  - carcass: furniture → **Własne dla płyt korpusu** (panel default) → **Własna płyta i obrzeże** of a role,
  - shelves / partitions: furniture → **Własne dla półek i przedziałów** (panel default) → **Własne dla tej sekcji** (inherited by sub-sections).
  Each level shows where the inherited finish comes from; checking "Własne…" starts from the inherited values (`InheritableFinish`).
- **Zastosuj do płyt korpusu, półek i przedziałów** sets on the boards already added the finish each one inherits (with its overrides); ordinary boards are not touched.

## Carcass boards (płyty korpusu – `src/carcass/carcass.ts`, panel `src/panels/CarcassPanel.tsx`)
A beginner-friendly layer on top of the boards + layout constraints ("core"): **Dodaj płytę** → **Płyty korpusu** adds the typical boards of a cabinet with one click – **Dach, Podłoga, Lewy bok, Prawy bok, Plecy** – each at most once (the board gets a `role`; a second top cannot be added). **Dodaj cały korpus / Dodaj brakujące płyty** adds all missing ones; **Grubość nowych płyt** sets their thickness (default 18 mm).
- **Relations** – every pair of neighbouring carcass boards meets at a corner and one of them **covers** (przykrywa) the other: it runs through to the furniture wall, the other one butts against its inner face. Stored once per pair (`CarcassRelations`), so "dach między bokami" and "bok przykrywa dach" are the same setting seen from the two boards. Pairs: dach / podłoga / plecy × lewy / prawy bok, plecy × dach, plecy × podłoga.
- **Defaults** (`DEFAULT_CARCASS_RELATIONS`): dach – przykrywa boki i plecy; podłoga – między bokami, przykrywa plecy; plecy – między bokami, pod dachem, nad podłogą; boki – przykrywają podłogę, pod dachem, przykrywają plecy.
- Clicking a board tile opens its relations (radio buttons, e.g. dach: *Nałożony na boki* / *Między bokami*; for dach / podłoga / plecy one row "Boki" sets both sides). They can be set **before adding** (a relation to a board not added yet applies once it is added) and **changed any time** – the boards are re-placed at once. A schematic (front / side / top view, drawn with the same code on a model furniture) shows the result; boards not added are dashed.
- **How it works** – no geometry of its own: a carcass board is an ordinary `Board` placed only with ordinary anchors marked `preset` (`presetAnchorSpecs`): the outer face of its thickness → its furniture wall; every other face → the inner face of the neighbour in that direction if the neighbour exists and covers it, otherwise the furniture wall (front → the front wall). Every carcass board is therefore fully determined and the Cassowary solver places it – so the carcass follows the furniture size, a changed thickness of a side, etc. like any joined boards.
- `syncCarcassAnchors` keeps wanted carcass joints (with offsets changed in the panel, e.g. back recessed 10 mm), removes the unwanted ones and adds missing ones; **a face joined by hand** (a chain in the scene) keeps the user's joint. Joints of free boards are never touched. Removing a carcass board gives its place back to the neighbours. When some of its joints were removed by hand the panel offers **Odtwórz wiązania**.
- **Board and edge banding** (`src/boards/finish.ts`, form `src/panels/FinishFields.tsx` – the same inputs as for an ordinary board): above **Dodaj cały korpus / Dodaj brakujące płyty** the default configuration of new carcass boards (board model + thickness + grain, obrzeże ABS incl. per-edge overrides A–D); in the tile of a board not added yet **Własna płyta i obrzeże** overrides it for that board (with the side names of its orientation). They apply when the board is added; **Zastosuj do dodanych płyt korpusu** sets them on the boards already added (override of the role, else the default). An added board shows its finish and is edited in **Szczegóły**.
- **Szczegóły** opens the board in "Płyty" (board model, bands, cut-outs, joints…). The orientation of a carcass board is locked (its role sets it). Tests: `src/carcass/carcass.test.ts` (incl. all 256 relation combinations – collision free and satisfied).

## Shelves and partitions (półki i przedziały – `src/sections/sections.ts`, panel `src/panels/SectionsPanel.tsx`, scene `src/scene/SectionOverlay.tsx`)
The second beginner-friendly layer on top of the core (like the carcass): left tool panel → **Półki i Przedziały**.
- **Sections (sekcje)** – the inside of the furniture is a tree of sections. At first the whole furniture is one section (the root: between the inner faces of the carcass boards present, the furniture walls where one is missing, from the back to the front). Adding shelves (horizontal boards) or partitions (vertical boards) to a section splits it: N dividers → N + 1 sub-sections (the space between two neighbouring dividers or a divider and the section edge). All dividers of a section are of one kind; a section between shelves can only get partitions, a section between partitions only shelves; the root takes either. Sub-sections are numbered from the bottom / from the left: "Sekcja 2.1" = the 1st sub-section of section 2.
- **Panel**: the section tree (click = select), the selected section with its size, **+ Dodaj półkę / + Dodaj przedział** (disabled with the reason when its place in the tree does not allow it; a new divider is added at the top / on the right), **Domyślne odsunięcie od frontu** (default 5 mm), its dividers (setback, *nadpisane* when changed per board, **Szczegóły**, **Usuń**), **Usuń podział tej sekcji**, **↑ Sekcja wyżej**; common thickness of new dividers (18 mm).
- **Scene**: the sections are 2D planes at the front of the furniture. Entering the mode highlights the root (the whole front); clicking a section enters it and highlights its sub-sections (blue), and so on down to a leaf (green). Clicking elsewhere on the front picks the section at the same level there; **right click** (without dragging – dragging still rotates the camera) or **Esc** → one level up; **click outside the furniture** → back to the root. Board clicks are ignored in this mode.
- **How it works** – no geometry of its own: a divider is an ordinary `Board` (`divider: 'shelf' | 'partition'`, orientation locked) placed only by generated joints (`preset`, `sectionAnchorSpecs`):
  - across the split axis (its thickness) it is joined on both flat sides – to the previous divider / section edge and to the next one – which the core treats as a centred board (`centeredPairs`): each divider sits in the middle of its neighbours, so the sub-sections are equally big (e.g. 2 shelves in 684 mm → 3 × 216 mm); the position can be changed per board in its joints (mm / %),
  - along the other in-plane axis it is stretched between the section edges, in depth from the back of the section to the front of the furniture with the section's **default setback** as the offset of the front joint – so the setback can be overridden per board in its joints. Changing the default moves every divider that still has the old value (and passes it on to sub-sections that inherited it).
  - `applyStructure` regenerates the carcass joints, then the divider joints (their frames depend on the carcass), then solves – so shelves follow the furniture size and carcass changes (e.g. a removed top). Joints changed per board are kept, faces joined by hand keep the user's joint; when some joints were removed by hand the panel offers **Odtwórz wiązania**.
- **Board and edge banding**: the default board (model + thickness) + obrzeże ABS of new shelves / partitions; a section can override it (**Własne dla tej sekcji** – `Section.finish`), which its sub-sections inherit unless they have their own (`effectiveSectionFinish`; the panel says where the inherited one comes from). A new divider takes the finish of its section (own / inherited), else the default. **Zastosuj do płyt tej sekcji** sets it on the dividers already there (also in sub-sections without their own – `dividersUsingSectionFinish`). Edge letters follow the board: horizontal (shelf) C = front, side (partition) D = front.
- **Layout of the dividers** (`Section.layout`, panel **Rozkład półek / przedziałów**):
  - **Równy** (default) – every divider is a centred pair between its neighbours, the sub-sections are always equally big,
  - **Ręczny** – the same pair of joints, but in **percent**: each divider sits at p % of the free space between its neighbours (p = size below / (size below + size above), the core's centred pair in % – `centeredPairs`). So the sub-sections keep their **proportions** when the furniture or a carcass board changes (e.g. 100 / 157,5 / 157,5 / 215 mm at 720 mm → × 1,286 at 900 mm). The panel lists the sub-sections with their sizes (editable – `setCompartmentSize`: the changed one and the last one change, the others stay). A new divider halves the last sub-section; removing one keeps the others in place (new joints of a manual section get their % from the current geometry – `repairManualPairs`).
  - **Dragging** in the scene (mode "Półki i Przedziały"): the orange strip over the front edge of a shelf / partition – LMB + drag moves it along the split axis (1 mm steps, `moveDivider`): the two sub-sections around it change, the other dividers stay (the % of the joints are recomputed from the new sizes); their sizes are shown while hovering / dragging. A click on the strip selects its section. Editing a size or dragging switches the section to **Ręczny**; **Równy** spreads them evenly again.
  - **Automatyczny** (`Section.auto`, panel **Automatyczne półki / przedziały** → **Dodawaj automatycznie**, **Co ile [mm]**; the root also chooses półki / przedziały): every divider **reserves** `pitch` mm – the first one starts `pitch` from the bottom / left of the section, the next `pitch` from the start of the previous one, as long as the whole board fits (pitch 500: section 500 mm – none, 700 – one at 500, 1200 – at 500 and 1000). Each divider hangs on the previous one (or the section edge) by ONE joint = the clear size of the compartment below in mm, so the compartments keep their sizes and the last one takes the rest. The dividers stay ordinary: sizes can be typed / dragged (the section stays automatic), dividers added and removed by hand (not put back while the section keeps its size). After every layout `maintainAutoSections` (run in a loop by `applyStructure`, also on a furniture resize and board edits) **removes** a divider the top / right edge of a shrinking section runs into and, when the section **grew** past its size at the last fill, **adds** new ones every `pitch` above the last one. The thickness / finish of the added boards are the defaults when the option was switched on. Changing the pitch spreads the existing dividers again; **Równy / Ręczny** or unticking switch it off (the dividers stay, manual layout). Automatic dividers do not limit the minimum furniture size (`autoRemovableDividers`) – they go away instead. Tests: `src/sections/autoFill.test.ts`.
- **Removing** a divider (panel, board list, Delete key) merges its two sub-sections: the one split further is kept and now spans both, the other one's dividers are removed too (if both are split, the upper / right one goes). When the last divider of a section goes, the section takes over the kept sub-section's dividers if that kind is allowed there, otherwise they are removed. Tests: `src/sections/sections.test.ts`.

## Joint modes: hinge and two-sided (`src/layout/hinges.ts`, `src/layout/constraints.ts`, `src/layout/solver.ts`)
Every joint in the board's **Wiązania** list has two switches under it:
- **zawias** (`AnchorConstraint.hinge`) – the board turns around the edge of this joint. **One hinge per board** – a board turns around one axis, so while one joint is a hinge the switch is disabled on its other joints (`otherHinge`, the reason names that joint). Allowed on an EDGE face of the board (not on its flat sides) joined to a **perpendicular board** or to a furniture wall (`hingeProblem`) – a door hinged on the carcass side, a flap on a shelf, an **opening top** hinged on its back joint… nothing is specific to fronts. The rotation axis runs along that edge on the outer flat side of the board, the free edge swings out of the furniture (100° around a vertical axis, 85° otherwise – `boardHinges`, `src/scene/HingedGroup.tsx`). Render only – the layout and the joints stay as they are. **Otwórz / Zamknij** appears on the tile of every hinged board (`scene/openBoards.ts` context), the toolbar **Otwórz zawiasy** opens them all. A board on a hinge moves, so touching it takes no edge band away (`hiddenBands(boards, movable)`).
- **obustronne** (`AnchorConstraint.twoSided` + `bias`) – like a chain in ConstraintLayout: a joint between two boards whose faces look at each other on an axis that is not the thickness of either (`twoSidedProblem`, e.g. right face of the left leaf ↔ left face of the right leaf). The offset is the **gap** between them and the solver adds a second equation: the middle of the gap sits at **podział** (`bias`, 0–100 %) of the span between the far faces of the two boards – `(low.max + high.min) / 2 = low.min + bias · (high.max − low.min)`. So a bigger gap takes half from each board (at 50 %), and both follow when the span changes (furniture resize). Turning it on keeps the current geometry (gap + podział from it – `setTwoSided`); editing either board by hand re-derives both (`rederiveOffsets`). The other board lists the joint too (its face is held – `heldFaces`, locked in the scene). Gap range: 0 … span − 2 mm; mm only.

## Fronts (fronty – `src/fronts/fronts.ts`, panel `src/panels/FrontsPanel.tsx`, `src/structure.ts`)
Left tool panel → **Fronty**. Doors / flaps built on the section tree and on the core joints.
- **Coverage**: a front covers a section – the whole of it or a run of neighbouring sub-sections (**Zakres frontu** od / do). Fronts never overlap: not in one section, and not between a section and its parent / sub-sections (a big front on a parent section blocks fronts in its sub-sections and vice versa – `coversConflict`, the reason is shown on the disabled button). A front whose sections disappear (a shelf removed…) is removed.
- **Picking in the scene**: click a section to enter it (PPM / Esc – up). **Ctrl (⌘) + click** a neighbouring sub-section adds it to the run for one front (the ones between are taken too; clicking an end of the run takes it off) – highlighted green in the scene and dashed in the panel tree, the same state as **Zakres frontu** od / do (`ctrlPickSection`, `selectionCovers`). **Enter** adds the front on the picked sections (like **+ Dodaj front**).
- **Front list**: clicking a front card (not its controls) marks it with a thin blue border and highlights the sections it covers in the scene (blue); clicking it again, another card or outside the furniture clears it.
- **Mounting**: **nakładany** (overlay) – in front of the carcass, covering the full thickness of the carcass boards around the opening and half of a shelf / partition (the neighbouring front takes the other half); the whole carcass and everything in it is set back by the front thickness so the front stays inside the furniture. **wpuszczany** (inset) – in the opening, flush with the carcass front; the shelves / partitions **behind** it (inside the covered area, not the ones bounding it) are set back by its thickness.
- **Opening** – named by how the FREE edge moves: **z lewej do prawej** (hinges on the right), **z prawej do lewej** (hinges on the left), **podwójny** (two leaves, hinges on both outer sides), **z góry na dół** (hinges at the bottom – a falling flap), **z dołu na górę** (hinges at the top).
- **Luz montażowy** split into **luz w poziomie** (left / right, also between the two leaves) and **luz w pionie** (top / bottom). Each value is the whole gap between two neighbouring elements (default 2 mm) and is applied half per side (1 mm + 1 mm), so neighbouring fronts / leaves are 2 mm apart. Both are joint offsets in the core (gap/2 − covered edge), A **negative gap** makes an overlay front bigger (e.g. −18 mm → the front covers the whole 18 mm shelf instead of a half). It never leaves the furniture (an edge past a wall is glued to the wall), a neighbouring front on the other side of that shelf / partition is pushed back and keeps its own gap, the leaves of a double front only touch (never overlap), inset fronts treat a negative gap as 0; two fronts extended over the same board are reported as overlapping on their cards. These limits are checked again on the solved layout (after a resize), as defaults, editable per front; płyta (model, grubość) / obrzeże / usłojenie inherited from **Parametry mebla** unless **Własne dla frontów**.
- **In the core – a front is an ordinary board** (1 board, 2 for a double front; `Board.front` only links it to the tool, like `role` / `divider`), placed by ordinary generated joints (`frontAnchorSpecs`): every edge → the plane bounding the covered area (carcass board / shelf / partition face or furniture wall) with offset = gap/2 − covered edge; across the depth → a **carcass board** (overlay: back face on the front edge of the side / top / bottom on the hinge side, inset: flush with it – the furniture front only when there is no carcass); the two leaves of a double front are joined by ONE **two-sided joint** (leaf L right ↔ leaf P left, offset = horizontal gap, podział 50 %). The joints on the hinge side are in **hinge mode**. Everything scales with the furniture / sections (e.g. a double front on a 1000 mm wide carcass: two 496 mm leaves). The modes of these generated joints follow the tool (otwieranie / podwójny) – disabled in the joint list.
- **Set-back** of the carcass boards and dividers (`recessByBoard`) is added to their front joints as a separate part of the offset (`AnchorConstraint.recess`, `applyRecess`), so a setback changed by the user is kept and the fronts can come and go. `applyStructure` (`src/structure.ts`) runs: carcass joints → shelf / partition joints → front joints → set-back → solve.
- **Opening in the scene**: **Otwórz / Zamknij** per front in the panel, **Otwórz wszystkie**, **Otwórz / Zamknij** on the tile of any board with a hinge joint and the toolbar checkbox **Otwórz zawiasy** (all hinged boards) – see *Joint modes* below.
- Removing a leaf (board list, Delete) removes the whole front; changing single ↔ double re-creates it.

## Resizing a board by its edges (`src/scene/BoardResizeEdges.tsx`, logic `src/boards/resize.ts`)
- Only the selected board (green outline). Hovering an edge highlights it (lime) and shows a resize cursor; **LMB + drag** changes the size, the current value is shown next to the edge.
- Edge along the board **height** → changes the **width** (from that side); edge along the **width** → the **height**; short edge along the thickness (a corner) → **both**. The thickness never changes. The opposite face stays in place (dragging the min side moves the position), the board stays inside the furniture, min 1 mm, 1 mm steps.
- The change goes through the normal board update – offsets of the board's own constraints on the moved face are re-derived, dependent boards follow.
- Edges are picked in screen space (document listeners, capture phase); the constraint handles (window listeners) win where both overlap (`src/scene/pointerClaims.ts`). Pressing an edge never starts the board drag / camera pan.

## Layout constraints (wiązania – 3D ConstraintLayout)
- Model: `src/layout/constraints.ts`, solver: `src/layout/solver.ts` ([Cassowary](https://constraints.cs.washington.edu/cassowary/) via `@lume/kiwi` – the algorithm behind Android ConstraintLayout / iOS Auto Layout), tests: `src/layout/layout.test.ts` (`npm test`).
- Every board has 6 faces: **lewa / prawa** (X), **dolna / górna** (Y), **tylna / przednia** (Z). An anchor glues a face of a board to a face on the same axis of the furniture or of another board: `face(board) = face(target) + raw offset [mm]` (the typed offset is a distance away from the target, see below). One anchor per face.
- Strengths: required (size ≥ 1 mm, size along the thickness axis = thickness) › inside the furniture › anchors › the other sizes keep their value (they give way to anchors on both sides → the board stretches, like `0dp`) › "stay" (a board keeps its place if nothing moves it). Conflicts don't throw – unsatisfied anchors are reported (toolbar, board card, furniture panel).
- There are no bulk joint tools (connect all touching boards / remove all joints) – joints are made by the carcass / sections / fronts, by chains in the scene and in the board card; they are removed one by one (chain click, the card) or with their board. `attachAllContacts` / `attachToContacts` remain in `constraints.ts` only to build layouts in the tests.
- Board card (edit mode) → **Wiązania**: list of the board's anchors with editable offsets, boards depending on it, adding an anchor (face → Mebel / board → target face; like a chain in the scene it **pulls** the board to that face – offset 0 – and the offset is then set in the list).
- **Handles in the 3D scene** (`src/scene/ConstraintHandles.tsx`) – shown only while a board is selected: a handle in the middle of each of the 6 faces of every board and of the furniture walls (squares). Selected board – green, other boards / furniture – blue, handles that can't start or end a chain – grey; **hovering a grey handle says why** ("inna oś niż uchwyt startowy", "to ta sama płyta", "takie wiązanie już istnieje", "wiązanie musi dotyczyć zaznaczonej płyty" – `connectionProblem`). Only meaningless connections are blocked; two boards may be joined more than once on the same axis and the solver decides what it does (a board squeezed between two planes ends at its minimum size and the chain turns red as unsatisfied). The automatic `attachAllContacts` (test helper) stays conservative – one joint per pair and axis. **Press a handle and drag** → a chain; **drop it on another handle** → the joint is created (the owner of the start handle is the dependent board, or the board at the end when the chain starts at the furniture). The chain **pulls** the dependent board: offset = 0 – opposite faces end up touching, faces of the same side aligned in one plane; the offset can then be changed in the panel. An existing anchor of the same face is replaced. **Esc** or dropping elsewhere cancels. Existing joints of the selected board are drawn as chains (red = not satisfied); **hovering a chain** turns it red and thicker and shows "× Kliknij, aby usunąć wiązanie", **clicking it removes the joint** (the boards stay where they are). Handles are picked in screen space by window listeners (capture phase), so pressing a handle never starts a board drag / camera pan, and they have a constant size on screen.
- **Offsets (odsunięcia)** are typed as a distance **away from the target plane**, the same on every face (`offsetDirection`): positive = into the furniture from its wall, away from the board the face touches, **recessed** behind the face of a board it is aligned with (e.g. shelf front → side front: +20 = shelf set back 20 mm). The model keeps `face(board) = face(target) + raw offset` along the axis (`anchorRawOffset`); before, the typed value WAS the raw axis value, so right / top / front faces needed negative offsets. Negative values are still accepted while the board stays inside the furniture (e.g. a top overlapping the fronts).
- **mm / %** – every offset has a unit switch (`unit`, `setAnchorUnit` keeps the board in place when switching). **%** = percent of the **free space** (`freeLimitValue`): 0 % = at the target plane, 100 % = the board touching the opposite furniture wall (a board hanging on one joint moves whole, so its size is taken off; a stretched board moves only that face). It stays linear, so the solver keeps the board at its relative place when the furniture / target changes (a shelf at 50 % stays in the middle of the free height).
- **The offset is limited** so the board cannot leave the furniture (`anchorRange`, from the current geometry): a board on one joint – 0 ≤ min face and max face ≤ furniture size; a stretched board – the face cannot pass its other face (min. 1 mm). The field clamps to that range (shown in its tooltip); the % switch is disabled when there is no free space on that axis.
- **A board joined on both flat sides** (the faces of its thickness axis – e.g. a divider chained to the left and to the right side of the carcass) cannot stretch, so the two chains put it in the **middle** between the two planes: `min + max = (planeMin + offset) + (planeMax + offset)` (`centeredPairs`). Both anchors then share ONE value (`centeredOffset` / `setCenteredOffset`), shown as a single row in the panel ("lewa ↔ prawa → środek między …"): in **mm** the distance of the board centre from that middle (signed: + = right / up / front, limited to ± half the free gap), in **%** the position between the planes (0 % = touching the min plane, 50 % = middle, 100 % = touching the max plane; `setCenteredUnit`). The pair is validated together: neither face touches its own plane, yet nothing is reported as unsatisfied. Two joints on the other axes stretch the board as before.
- **Moving / resizing a board others hang on** works: the board the user has just edited is pinned ABOVE the anchors for that solve (`solveLayout(..., pinnedId)`), so the boards hanging on it follow instead of pulling it back; if such a board is held somewhere else too, the conflict is reported as an unsatisfied joint.
- **Resizing a board others hang on** also works: a board with no joint of its own on that axis keeps its size harder than a dependent one (`SIZE_FREE` vs `SIZE_DEPENDENT`), so widening it stretches the boards anchored to it instead of snapping back.
- **What the joints block** (`boardLocks`): a joint on an axis fixes the board's POSITION along it (it can't be dragged there, the position field is read-only); joints on BOTH faces of an axis fix the SIZE as well (dimension field read-only, the edges moving those faces can't be dragged). The distance to the plane a board hangs on is changed only by the joint's **offset in the panel**. Only a changed orientation (the faces swap axes) re-derives the offsets.
- **Removing a joint puts the board back**: every anchor keeps the geometry of its dependent board from just before it was made (`restore`). When the last joint on that axis goes away, the position and the size along it return to that snapshot (`restoreAfterRemoval` / `removeAnchorsWithRestore` – used by the chain click, the panel and by removing a board).
- Changing the furniture size solves the layout – e.g. a carcass (sides, inset bottom / top, shelf) widens, heightens and deepens with the furniture.

## Board models (modele płyt – `src/boards/boardCatalog.ts`, picker `src/panels/BoardModelPicker.tsx`)
- The veneer (okleina) list is gone – the look of a board follows from its **board model**: a concrete board of a manufacturer (e.g. Egger H1145 ST10), stored on the board as `materialId` (`BoardParams`). The model sets the **face texture**, the **thickness** and whether the **grain direction** matters.
- The catalog comes from the backend: `GET /api/boards/catalog` (`src/api/boardCatalog.ts`, loaded once in `App`; `useBoardCatalog` re-renders when it arrives). A model: `brand`, `type`, `seriesCode`, `name`, `textureUrl` (image the texture is made from), `textureSize` (real size of the image in mm), `grainMatters`, `thicknesses` (variants in mm), `color` (average colour – swatch / fallback). Until the catalog is loaded, or when the backend is down, only the built-in default board is available (and the picker says so).
- **Picker "Płyta"** – a drop-down tree **Typ** (Płyta wiórowa laminowana, MDF, HDF) → **Marka** (Egger, Kronospan …) → **model** (series code + decor name), with a search field. Every type has the brand **Surowe (sklejki, płyty wiórowe...)** with the **default raw chipboard** (`raw-chipboard`) – it is selected by default everywhere unless something in the inheritance chain overrides it.
- **Grubość** (`BoardModelFields`): a list of the model's thickness variants; a model with no variants (e.g. raw MDF) → any thickness typed by hand. Changing the model keeps the thickness if the new model offers it, else 18 mm, else the nearest variant (`fitThicknessToModel`).
- **Kierunek usłojenia** (`BoardParams.grain`, `GrainField`): the two edges the grain runs between (like a groove direction) – **A–C** = from edge A to edge C (along the board height), **B–D** = from edge B to edge D (along the width); default A–C; locked for a model with `grainMatters = false` ("nie dotyczy tej płyty").
- The model + thickness + grain + edge banding form the `BoardFinish` – the unit of the inheritance chain: **Parametry mebla** → panel defaults (**Płyty korpusu**, **Półki i Przedziały**, **Fronty**) → per carcass role / per section overrides. The separate "Grubość nowych płyt / frontu" fields were removed – the thickness comes with the board. "Zastosuj …" buttons set model, thickness, grain and bands.
- Render (`src/boards/BoardMesh.tsx`, `src/boards/boardTextures.ts`): the image is loaded through the backend proxy `GET /api/boards/{id}/texture` (same origin → usable by WebGL), once per model; boards use clones scaled to `textureSize` (UVs are in mm). The grain of a catalog image runs along its **height**, so A–C (along the board height) uses it as it is and B–D turns it by 90°. While loading – the average colour. The default raw chipboard keeps the procedural chipboard texture (`chipboardTextures.ts`); the narrow sides show the core of the type (chipboard, or the MDF / HDF colour) unless an ABS band covers them. Colliding boards get a red glow on top of their texture.

## Edge banding (okleiny krawędzi / obrzeża – catalog `src/boards/edgeBandCatalog.ts`, form `src/panels/EdgeBandingFields.tsx`)
- Same system as the board models: the band models come from the backend (`GET /api/edge-bands/catalog`, loaded in `App` by `src/api/edgeBandCatalog.ts`). A band: `brand`, `type`, `seriesCode`, `name`, `textureUrl` + `textureSize` (decor image), `grainMatters`, `thicknesses` (variants in mm), `widths` (roll widths in mm), `color`, `matchingBoardIds` (boards of the same decor).
- **Picker** (`CatalogTreePicker`, shared with the board picker): tree **Typ** (ABS, PCV, Melamina) → **Marka** (Egger, Spander, Schilsner, Uniwersalne) → band, with a search field. On top: **Brak obrzeża** (and **Jak wszystkie** for an edge override) and **Pasujące do płyty** – the bands whose decor matches the chosen board model.
- A band for all edges + **Nadpisz wybrane krawędzie** – every edge (A–D and the cut-out edges) can use the common band, have no band, or another band with its own thickness.
- **Thickness**: a list of the band's variants; a band without variants (e.g. PCV "Czarne mat") → any value typed by hand (0,1–10 mm, precision 0,01 mm). A new band keeps the thickness if it offers it, else 1 / 0,8 mm, else the nearest variant (`fitBandThickness`).
- **Roll width**: when the board is thicker than the widest roll of a band used on it, the form shows a warning (`bandWidthProblem`).
- Render: the band strips get the decor image laid ALONG the edge (`edgeBandTexture` in `src/boards/boardTextures.ts`, via the proxy `GET /api/edge-bands/{id}/texture`), or the band colour. A band whose model is not in the catalog (not loaded yet / backend down) keeps its thickness and is drawn grey (`resolveEdgeBand` no longer drops it). Edge tags use the band colour (white letters on dark bands).
- Edges are named **A, B, C, D clockwise**: vertical board (seen from the front) A top, B right, C bottom, D left; horizontal board (seen from above, front at the bottom) A back, B right, C front, D left. Banding model in `src/boards/edgeBanding.ts`.
- The board dimensions are **gross (brutto)** – they include the bands. The render offsets the board outline inwards by the band thickness of every edge (core) and draws the bands as thin extruded strips, so core + bands = the entered outline (`src/boards/boardGeometry.ts`; at perpendicular joints the band of the edge along the width – A / C and horizontal cut-out edges – runs through, the other fits between; chamfer joints are mitred). Collisions and limits use the gross size. Bands thicker than the board (A + C ≥ height or B + D ≥ width) are reported as an error.
- Edge labels in the scene (`src/boards/EdgeLabels.tsx`) – styled like the X / Y / Z axis labels: a short line out of the middle of the edge and the letter, in the band colour (grey dashed = no band). Shown only on the selected (edited) board – always.
- The board tile shows the edges as small coloured tags with the band thickness.

## Cut-outs (wycięcia – trapez, L-ka, zaokrąglenie, U)
- The add and edit forms have a **Wycięcia** section (`src/panels/CutoutsFields.tsx`): a 2D view of the board with the cut-outs, buttons **+ Skos** (chamfer – with Y = full height it makes a trapezoid), **+ Wycięcie L** (rectangular corner notch), **+ Zaokrąglenie** (rounded corner, radius R) and **+ Wycięcie U** (rectangular slot in an edge), a list of the cut-outs and **⤢ Edytor 2D** – a bigger floating 2D editor (`src/panels/ShapeEditor2D.tsx`).
- Model (`src/boards/cutouts.ts`):
  - corner cut-outs (max one per corner AB, BC, CD, DA): chamfer / notch with X / Y from the corner, radius with R (stored as x = y = R),
  - U slots (any number, on edges A–D): position from the reference corner of the edge (A → left-top, C → left-bottom, B → right-bottom, D → left-bottom), width along the edge and depth into the board.
  - The 2D frame is the same for both orientations: A at the top (vertical board seen from the front, horizontal board seen from above with the front at the bottom).
- Rules: a valid (non self-intersecting) outline, **every straight edge either removed completely or at least 1 mm long** and no material web narrower than 1 mm (`MIN_EDGE_MM`). **With edge bands the same rules apply to the core** (outline − bands, `areBandsValid`): a short edge or web needs 1 mm plus the bands of its neighbours (e.g. a rib between two U slots with 1 mm bands ≥ 3 mm), a banded radius ≥ 1 mm + band. Editing (inputs, scrub, dragging, new cut-outs) respects it; if a thicker band is chosen later, the shape is kept, an error is shown and the cut-out can still be edited to fix it. The allowed values can have gaps (e.g. a chamfer Y of 719–720 mm on a 720 mm board: only 719 or exactly 720), so values are snapped to the nearest allowed one (`constrainCutoutParam`); a cut-out cannot be dragged "through" another one.
- The points of the cut-outs can be dragged in the 2D view (chamfer / notch: X / Y, radius: the two tangent points = R, U: both mouth ends = position / width, bottom middle = position + depth; Shift – 10 mm, Alt – 0,1 mm; a focused point moves with the arrow keys). Labels show the X / Y distances from the reference corner of the cut-out (0, 0) and avoid overlapping. The numeric inputs have scrub handles and snap to the allowed values (`NumberField` `normalize`).
- Stored cut-outs are not changed when the board gets smaller (e.g. while typing a new width) – `boardCutouts()` returns them fitted to the current size.
- New edges get letters **E, F, G…** (in the order of the cut-outs: chamfer 1, notch 2, radius 1 arc, U 3 – wall, bottom, wall) and stable keys (`<cutoutId>:s|x|y|r|w1|b|w2`). The common band applies to them and they can be overridden in **Nadpisz wybrane krawędzie** like A–D; a side split by U slots keeps its letter for all its parts. Overrides of a removed cut-out are dropped.
- The scene renders the outline with `ExtrudeGeometry` (hit area + outline edges, core, band strips; arcs are tessellated and banded as one strip). Bands thicker than a short edge / web / radius are reported as an error. Collisions still use the gross bounding box.

## Grooves (frezowania – `src/boards/grooves.ts`, render `src/boards/grooveGeometry.ts`, panel `src/panels/GroovesFields.tsx`, 2D `src/panels/GrooveView2D.tsx`)
- Board form → **Frezowania**: any number of rectangular channels, each **width × depth × length**, on **strona 1** (the face seen in the 2D view: przód / prawa strona / góra), **strona 2** (the opposite face) or in an **edge A–D** – an edge only when it has **no edge band** (the add button / option is disabled with the reason; an edge whose band is left out because it touches another board counts as bare; a groove on an edge that gets a band later is flagged and not milled).
- A face groove runs along **A–C** (width) or **B–D** (height), positioned from edge C / D; an edge groove runs **along its edge** (positioned across the thickness from strona 2, a new one in the middle) or **across the edge** (**Kierunek → w poprzek krawędzi**, `across`): through its width, i.e. across the board thickness – positioned along the edge from D (A / C) or C (B / D), a new one in the middle of the edge; its length runs through the thickness from strona 2 (**Przez całą grubość** by default, unticked → start + length = a pocket in the edge). Its cross-section shows that run through the thickness. New grooves are 4 × 8 mm and run **through the whole available length** (**Na całą długość** – the board, or the straight part(s) of an edge with cut-outs); unticked → start + length. The depth leaves at least 1 mm of material; every value is limited (`grooveRange`, `fitGroove` – grooves follow a resized board).
- **2D views** like the cut-outs: **rzut** (strona 1 filled, strona 2 dashed – seen through the board, edge grooves as hidden channels from the edge) and the **przekrój** (cross-section) of the selected groove, with draggable points – position across, width (far wall), depth (bottom), start / end when not through (Shift 10 mm, Alt 0,1 mm, arrow keys); **⤢ Edytor 2D** opens a bigger window with the list.
- **3D**: the grooves are cut out of the board core and its band pieces with CSG (`three-bvh-csg`), the channel walls in raw chipboard (slightly darker). Needs `npm install` (new dependencies `three-bvh-csg`, `three-mesh-bvh`).

## Numeric inputs (`src/ui/NumberField.tsx`)
- All numeric board inputs (add + edit) are range-limited so that a board **never leaves the furniture** (typing and scrub handles alike): a dimension can reach at most the furniture wall from the board's current position (static limits 1–5000 mm, thickness 1–200 mm – `BOARD_PARAM_LIMITS`), the position is 0 … furniture size − board size on every axis (`boardParamLimits` / `boardPositionLimits`, `src/boards/board.ts`). Changing the orientation shrinks / moves the board into the furniture if needed (`fitBoardToFurniture`); the add form is fitted to the furniture too. The allowed range is shown next to each field. Typed values outside the range are clamped on blur / Enter. Values may be fractional – typed with a decimal comma or dot (`18,5` / `18.5`), shown with a comma; dimensions, positions and the furniture size have a precision of 0,1 mm (`DIMENSION_STEP`, `src/ui/format.ts`), band thickness 0,01 mm. ArrowUp / ArrowDown change the value by 1 mm (Shift ×10, Alt ×0.1).
- **Scrub handle** (⇕ next to every input): press and hold the left mouse button and move the mouse up (increase) / down (decrease) – 1 mm per pixel, Shift ×10, Alt ×0.1.
- **Moving a board with the mouse** (`src/boards/BoardMesh.tsx`): first select the board (click it in the scene or its tile – green edges), then drag it with the left mouse button – it moves in the **XZ plane** (horizontal plane through the grabbed point); hold **Shift** to move it along **Y** (vertical plane facing the camera; Shift can be pressed / released during the drag). The position is clamped so the board never leaves the furniture and rounded to whole millimetres; collisions with other boards are allowed and shown in red. While a board is dragged the camera pan is disabled (dragging elsewhere still pans). Only the selected board is draggable and only when it is the nearest board under the cursor. The legend (bottom left) shows these instructions while a board is selected.
- Clicking a board tile in the list (or **Edytuj**) opens its edit mode and highlights the board in the scene with **green edges**; **Gotowe** / closing the panel removes the highlight.
- **Delete** (or **Backspace** – the Delete key of a Mac keyboard) removes the selected board (the one with green edges) – the same as **Usuń** on its tile (joints go away, boards hanging on it return to where they were; a carcass board gives its place back to its neighbours). Ignored while typing in an input and inside the 2D shape editor.
